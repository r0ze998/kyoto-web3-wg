# 京都WG 課題構造ノート

京都の Web3 ワーキンググループの準備に使う研究ツールです。地域活動・文化資産・公共財的資源・関係人口について、「誰のどんな負担を、どの仕組みで減らし、誰が費用を払うか」を判断することを目的にしています。

使う順番は、候補比較 → 未確認事項の抽出 → ヒアリング計画 → 最小実証案 です。

> ここに載っている課題と構造は、公開資料にもとづく仮説です。現地ヒアリングは行っていません。費用はすべて試算か未確認で、見積は取っていません。

## 使い方

ビルドもログインも不要です。

- `index.html` をブラウザで直接開く（file:// で動きます）
- またはローカルサーバーで開く：`npx serve .`（`python3 -m http.server` でも可）

あなたが入力した回答・メモ・検証状態・費用の変更は、ブラウザの localStorage に保存されます。
「保存・出力」画面では次のことができます。

- 変更を JSON に書き出す／JSON から復元する（端末を移るときやバックアップに使います）
- 打ち合わせ用の短い要約と、出典付きの詳細を印刷・PDF にする
- 同じ内容を Markdown で書き出す

## 画面

| 画面 | 内容 |
|---|---|
| 課題カード | 8課題。8項目（困りごと・業務の流れ・既存手段・仕組み・支払い主体・チェーンなし比較・副作用・否定条件）で整理。検索・絞り込みあり |
| 関係者 | 課題ごと／関係者ごとに、負担・利益・権限を比較 |
| 現状⇔提案 | 案ごとに、現状と提案後の流れを並べる |
| 候補比較 | 3案を9つの観点で比較。総合点は付けず、文章と「根拠の強さ」で示す |
| 未確認事項 | 25件。案の成否を左右するものに印。状態を更新できる |
| ヒアリング | 27問。回答・根拠・判断の変化を記録（初期状態は空欄） |
| 実証案 | 3案。対象・人数・費用の仮定（試算／見積／未確認を区別）・指標・中止条件 |
| 事例・主張・出典 | 57事例、249主張（事実／当事者の主張／推測）、192出典。検証状態を更新できる |

## データの構成

画面とデータは分けてあります。

- `data/research/*.json`：調査結果（出典・主張・事例・見つからなかった情報）。A 地域活動、B 文化資産、C 公共財・通報・DePIN、D 関係人口・地域DAO、E 非Web3の類似の仕組み、F 試算の基準
- `data/analysis.json`：課題カード、関係者、候補案、未確認事項、問い、実証案。主張は ID（例 `A-C08`）で参照する
- `data/bundle.js`：上の2つをまとめた自動生成ファイル。直接は編集しない

データを編集したら、次を実行します。

```sh
node tools/build-data.mjs           # 参照の整合性を確認し、bundle.js を作り直す
node tools/build-data.mjs --check   # 確認だけ行う
```

ビルドでは次の整合性を確認し、違反があれば止まります。

- 存在しない主張ID・出典IDを参照していないか
- 事実と当事者の主張に出典があるか
- 初期データに「見積」や「ヒアリング回答」が入っていないか（創作の防止）

## 検証

```sh
node tests/e2e.mjs [出力ディレクトリ]
```

Chromium の実ブラウザで次の項目を確認します。

- 全画面の描画
- 主要な導線
- 検索・絞り込み
- 再読み込み後の保存
- JSON の保存・消去・復元
- 他の形式の JSON を拒否すること
- PDF の出力
- モバイル幅（390px）で横にはみ出さないこと

スクリーンショットと PDF は出力ディレクトリに保存されます。
