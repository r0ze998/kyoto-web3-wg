# 京都WG 課題構造ノート

京都の Web3 ワーキンググループの準備に使う研究ツールです。地域活動・文化資産・公共財的資源・関係人口について、「誰のどんな負担を、どの仕組みで減らし、誰が費用を払うか」を判断することを目的にしています。

まず「最初に読む」で結論を読み、そのあと候補比較 → 未確認事項の抽出 → ヒアリング計画 → 最小実証案 の順に使います。

> ここに載っている課題と構造は、公開資料にもとづく仮説です。現地ヒアリングは行っていません。費用はすべて試算か未確認で、見積は取っていません。

## 使い方

ビルドもログインも不要です。

- `index.html` をブラウザで直接開く（file:// で動きます）
- またはローカルサーバーで開く：`npx serve .`（`python3 -m http.server` でも可）

あなたが入力した回答・メモ・検証状態・費用の変更は、ブラウザの localStorage に保存されます。
「保存・出力」画面では次のことができます。

- 変更を JSON に書き出す／JSON から復元する（端末を移るときやバックアップに使います）
- 打ち合わせ用の短い要約と、出典付きの詳細を印刷・PDF にする
- 同じ内容を Markdown で書き出す

初期データだけの PDF（利用者の変更を含まない）は `node tools/export-pdf.mjs [出力ディレクトリ]` でも作れます。

|---|---|

| 課題カード | 10課題。8項目（困りごと・業務の流れ・既存手段・仕組み・支払い主体・チェーンなし比較・副作用・否定条件）で整理。検索・絞り込みあり |
| 関係者 | 課題ごと／関係者ごとに、負担・利益・権限を比較 |

| 候補比較 | 5案を9つの観点で比較。総合点は付けず、文章と「根拠の強さ」で示す |

| ヒアリング | 34問。回答・根拠・判断の変化を記録（人に聞く問いは空欄で開始。公開資料で確かめた2問だけ記入済み） |

## データの構成

画面とデータは分けてあります。

- `data/research/*.json`：調査結果（出典・主張・事例・見つからなかった情報）。A 地域活動、B 文化資産、C 公共財・通報・DePIN、D 関係人口・地域DAO、E 非Web3の類似の仕組み、F 試算の基準、G・H 未確認事項の補足調査、I 海外DePINの経済性、J 日本のDePINと参加型センシング、K 京都の買い手候補。主張には照合結果（`verification`）が付く
- `data/analysis.json`：課題カード、関係者、候補案、未確認事項、問い、実証案。主張は ID（例 `A-C08`）で参照する
- `data/docs.json`：文章で読む画面（最初に読む・DePIN分析・アイデア一覧の前書き）。本文中の `[[K-C19]]` は根拠の主張
- `data/ideas.json`：アイデア一覧の15案
- `data/bundle.js`：上の2つをまとめた自動生成ファイル。直接は編集しない

データを編集したら、次を実行します。

```sh
node tools/build-data.mjs           # 参照の整合性を確認し、bundle.js を作り直す
node tools/build-data.mjs --check   # 確認だけ行う
```

ビルドでは次の整合性を確認し、違反があれば止まります。

- 存在しない主張ID・出典IDを参照していないか
- 事実と当事者の主張に出典があるか
- 初期データに「見積」や「ヒアリング回答」が入っていないか（創作の防止）

## 出典との照合（2026-10-23）

根拠の主張572件はすべて、調査した担当とは別の担当が出典を開いて1件ずつ照合しています（照合の途中で追加した主張も、さらに別の担当が照合し直しました）。

| 結果 | 件数 |
|---|---|
| 照合済み（記載どおり） | 403 |
| 訂正済み（数値・主語・断定の強さなどを修正） | 153 |
| 更新済み（新しい公表値に差し替え） | 16 |

照合の結果はパッチ（JSON）にまとめ、`node tools/apply-verification.mjs <patch.json>` で `data/research/*.json` に反映します。各主張の `verification.note` に、何をどこで確かめたかが残ります。

分析（`data/analysis.json`）と読みもの（`data/docs.json`・`data/ideas.json`）は、照合後の主張に照らして別の担当が独立にレビューしました（それぞれ34件の指摘をすべて反映）。

## 検証

```sh
node tests/e2e.mjs [出力ディレクトリ]
```

Chromium の実ブラウザで次の項目を確認します。

- 全画面の描画
- 主要な導線
- 検索・絞り込み
- 再読み込み後の保存
- JSON の保存・消去・復元
- 他の形式の JSON を拒否すること
- PDF の出力
- モバイル幅（390px）で横にはみ出さないこと

スクリーンショットと PDF は出力ディレクトリに保存されます。
